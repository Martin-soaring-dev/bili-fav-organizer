# B站收藏夹智能整理：快速上手

适用 v0.204 界面。首次使用建议先走一遍手动模式，确认每一步的结果；熟悉后可以使用快速模式。

**完整流程：下载运行 → 登录 B 站 → 配置模型 → 扫描 → 生成画像 → 分析 → 人工复核 → 执行。**

## 一、下载并登录

| 准备什么 | 用来做什么 |
|----------|------------|
| Windows x64 电脑 | 运行便携版程序，通过浏览器操作。 |
| 手机 B 站 App | 扫码登录自己的 B 站账号。 |
| 模型服务的 API Key | 在下一步连接模型，用于生成画像和归类建议。 |

### 1. 下载并运行

1. 打开 [最新 Release](https://github.com/Martin-soaring-dev/bili-fav-organizer/releases/latest)，在 **Assets** 中下载 `BiliFavOrganizer-Windows-x64-<版本标签>.zip`。例如 v0.204 的文件名是 `BiliFavOrganizer-Windows-x64-v0.204.zip`。
2. 把 ZIP **完整解压**到可写入的文件夹，再双击 `BiliFavOrganizer.exe` 或 `BiliFavOrganizer.bat`，两者都用于启动程序。
3. 浏览器会打开 <http://127.0.0.1:8080>。未自动打开时，保持程序运行，手动访问这个地址。

便携包已带运行环境，无需安装 Python。请保留黑色控制台窗口，关闭它会停止服务。`Source code.zip` / `Source code.tar.gz` 是源码，`.sha256` 是校验文件，都不是直接运行的便携包。

### 2. 登录 B 站

在“连接配置”中选择“二维码登录（推荐）”，用手机 B 站 App 扫码并确认。确认登录成功后，可点击“测试 Cookie”检查；二维码失效时刷新二维码再扫。

B 站登录凭据保存在本机，模型 API Key 也会保存在本机。不要把这些凭据、整个个人数据目录或未遮挡的设置截图发给别人。

## 二、配置模型

### 3. 添加供应商、测试并选择模型

“供应商”是提供 AI 服务的平台；“模型”是该平台内具体使用的 AI。**B 站登录与模型配置是两件事，两边都需要完成。**

1. 点击“管理模型”。在“快速添加预设”中选择你已有账号的平台，点击“添加”；也可以点“新增供应商”，自行填写名称和 `base_url`。
2. 在对应供应商控制台创建、复制自己的 **API Key**，填入程序并点击“保存”。使用预设时，地址通常已填好；自定义地址请按供应商的 OpenAI 兼容接口说明填写。
3. 选中供应商，点击模型区域的“刷新”。在弹窗中选中要添加的模型，再点“保存所选”。**刷新列表后还要保存选择**，模型才会加入本地列表。
4. 点击“测试”，只勾选你准备使用的模型，点击“开始测试”。测试通过时会显示绿色状态点。
5. 点击该模型名称，点“激活”，再点“完成”；或者回到主页面选择供应商和模型，点击“保存配置”。最后点击“测试模型连接”，确认当前选中的模型可用。

如果列表刷新失败，也可点“新增模型”填写供应商提供的模型 ID。若上下文、最大输出显示未知，按供应商官方规格补填。第一次使用可先保留程序中的批大小、并发和请求间隔；不要随意提高并发或填写夸大的模型规格。

程序内提供 [AMD Token Factory](https://developer.amd.com.cn/radeon/tokenfactory) 和 [SiliconFlow](https://cloud.siliconflow.cn/) 等供应商预设。可用模型、额度和费用请查看各自控制台。生成画像和归类分析会调用模型服务，并将所需的视频信息发送给你选定的模型供应商。

## 三、第一次整理：按手动模式逐步操作

### 4. 获取收藏明细

切换“手动模式”，点击“刷新收藏夹目录” → “选择扫描范围” → 选择收藏夹 → “保存选择” → “开始扫描”。通常保留“继续未完成/变化的夹”和默认 2 秒请求间隔。

首次需要读取内容并建立本地索引，可能较慢；后续会复用已有数据并处理变化。耗时受收藏数量、网络和接口状态影响。**为了后续能生成目标收藏夹画像，首次请扫描所有需要参与整理的收藏夹。**

看到扫描完成且没有待处理异常，再继续下一步。若提示数量不一致，先按第四部分处理。

### 5. 生成收藏夹画像

打开“收藏夹画像” → “刷新列表” → “全选 active” → “生成缺失 / 过期画像”。

画像是 AI 根据夹内内容总结出的主题和收纳范围，用于判断视频该放哪里。`active` 指参与整理的收藏夹。默认收藏夹作为“未分拣收件箱”，不生成画像，也不能作为移入目标。

等待所有**有内容且参与整理**的收藏夹拥有完整扫描和当前画像。即使只想整理默认收藏夹，作为目标的其他收藏夹也需要画像。这一步会调用模型，首次处理大量内容时可能消耗较多额度。

### 6. 让 AI 生成归类建议

切换到“内容整理”，点击“开始分析”。首次先保留默认批大小和并发，重建索引选“不重建（仅分析新增）”。已有有效结果会复用；数量较多时请耐心等待。

这一步产出的是**建议方案**，尚未执行 B 站收藏夹的移动或删除。

### 7. 查看并确认方案

点击“加载分析结果” → “查看详情”，检查视频的目标收藏夹，修改不合适的归类，暂不处理的条目可设为“跳过”。确认无误后点击“确认方案（进入执行）”。

如果把失效视频标记为删除，也要一起复核。**点击“确认方案”后，还需要点击“开始执行”才会写入 B 站。**

### 8. 执行，并到 B 站检查结果

点击“开始执行”，按确认后的方案移动或删除内容。保留默认写操作间隔，观察进度和日志；完成后到 B 站核对收藏夹。

如果出现风控或“结果不确定 / unknown”，先核对实际状态和日志，再处理待执行项。不要直接重复提交不确定的写操作。

### 熟悉后：快速模式怎么用？

选择“快速模式”，再选择业务：**“内容整理”**用于归类视频；**“收藏夹整理”**用于生成收藏夹合并建议。点击“开始自动整理”，程序会串起目录、扫描、画像和建议生成，在需要人工复核时停下。

快速模式仍需要你复核方案并主动执行；遇到扫描异常时会暂停，处理后再继续。首次只想归类视频时，选“内容整理”即可。

## 四、遇到问题时，按这里检查

### 收藏夹数量不一致，例如 B 站 32 条、程序读取 31 条

数量差异可能来自隐藏失效内容，也可能是同步延迟、扫描期间内容变化或临时接口异常，不能只凭差异确定原因。

按提示窗口的顺序选择处理方式：

1. **推荐：去 B 站手动清理。** 点击“前往 B 站清理”，检查对应收藏夹并按需要处理失效内容；回到程序点击“我已处理，重试扫描”。
2. **不推荐：由程序自动清理。** 会修改 B 站收藏夹；展开警告并主动勾选同意后，才能“确认自动清理并重扫”。该操作不是只读刷新。
3. **刷新收藏夹并重扫。** 可尝试解决暂时的数量同步问题，不会清理内容。

只有重扫验证一致，后续整理才会恢复。关闭提示不会解除阻断；仍有异常时，可点击首页“查看处理提示”重新打开。上次清理结果不确定时，先去 B 站核对，再重试扫描。

### 其他常见问题

| 现象 | 先检查什么 |
|------|------------|
| 找不到程序，或者双击不能运行 | 下载的是带版本号的 Windows ZIP，并已完整解压；运行程序时保留整个解压目录。 |
| 浏览器打不开本地页面 | 黑色控制台窗口是否仍在运行；手动打开 `http://127.0.0.1:8080`，查看启动报错。 |
| B 站登录失败 | 用手机 B 站 App 确认扫码；刷新过期二维码，登录后测试 Cookie。 |
| 模型测试不通过 | Key、供应商地址和模型 ID 是否对应；该模型是否有访问权限、余额或额度；查看具体错误。 |
| 测试绿了，但开始整理仍提示没模型 | 主页面是否选中了正确的供应商和模型，并保存配置或激活。 |
| 不能开始分析或合并建议 | 是否有未解决扫描异常；所有有内容的 active 收藏夹是否已完整扫描并生成当前画像。 |
| 扫描、画像或分析很慢 | 首次需要建立索引和生成结果；查看进度与日志，先保留默认间隔，勿因等待频繁重启。 |
| 风控、限流或结果不确定 | 停止相关任务，按日志检查；写操作结果不确定时先去 B 站核对，避免重复操作。 |

### 升级、数据位置和反馈

升级时先关闭旧程序，下载新版便携 ZIP 并解压到新文件夹，再启动新版本。同一 Windows 用户的数据默认保存在 `%LOCALAPPDATA%\BiliFavOrganizer\`，升级程序不会清除它。按 Win+R，输入该路径即可查看。

换电脑时，可通过“导出项目数据”与“读取项目数据”迁移收藏索引、画像和整理结果；新电脑仍需重新登录 B 站、设置供应商和模型。导出文件不包含 Cookie、API Key 或供应商/模型配置。

隐藏失效视频场景目前主要在模拟环境验证，仍需要实机反馈。遇到问题请到 [GitHub Issues](https://github.com/Martin-soaring-dev/bili-fav-organizer/issues) 说明版本、所在步骤、报错、远端数量与扫描数量，并附遮挡凭据后的截图或相关日志。数量不一致的反馈可直接补充到 [Issue #6](https://github.com/Martin-soaring-dev/bili-fav-organizer/issues/6)。
