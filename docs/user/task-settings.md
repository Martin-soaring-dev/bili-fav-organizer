# 任务数量、并发与间隔

高级设置 → 任务数量与请求间隔。数字输入框支持任意范围内的十进制整数，输入后移开焦点保存，也可点击“全部保存”。小数、指数形式、负数、空值和超范围值不会保存；后端同样拒绝非整数。

| 操作 | 参数 | 范围 / 单位 | 生效方式 |
|---|---|---|---|
| 收藏夹扫描 | 扫描读取间隔 | 2–60 秒 | 每个远端读取请求之间的最小间隔 |
| 内容移动、删除 | 间隔；每批上限 | 1–60 秒；1–1000 条 | 远端写操作串行执行，移动和删除各自组批 |
| 收藏夹修改、合并、删除 | 操作间隔 | 1–60 秒 | 改名、简介发布、删除逐夹调用 |
| 内容匹配分析 | 每批上限；同时请求数 | 1–1000 条；1–4 | 实际 AI 请求，超出上下文时自动缩批 |
| 收藏夹画像 | 每批内容上限；同时请求数；请求间隔 | 1–1000 条；1–4；1–60 秒 | 全部可用内容分批压缩，压缩批次可并行，最终统一综合；仍服从模型 TPM |
| 收藏夹整理分析 | 全局比较 | 全部符合条件的画像；1 个请求 | 需要跨夹比较，不按固定夹数切批，故没有独立批大小和并发参数 |

扫描数量由实际收藏 ID 清单决定，不能设置成仅扫描前 N 条并声称扫描完整。正常不超过 1000 条的收藏夹，完整 IDs 一次，缺失明细最多一次；全部已有明细时只读 IDs。单条明细未返回会显示待补，不会因而把整夹重新分页或把该项判为失效。历史超 1000 条收藏夹的兼容路径见 [API 历史记录](../testing/favorite-api-history.md)。

新画像参数默认每批 1000 条、并发 1，保持原先串行行为。旧配置中画像间隔为小数时，界面向上取整显示；在用户保存之前不改写旧配置。参数在后续任务启动时读取。
