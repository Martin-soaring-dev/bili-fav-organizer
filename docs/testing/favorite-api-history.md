## 本次修复针对的问题

用户截图显示：完整 ID 清单之后，infos 少返回 1 条，于是程序把整夹退回 16 页读取。
这混淆了“已确认的收藏关系”与“可取得的视频明细”。修复后以完整 ID 清单确认成员；明细缺项保留 ID 并标注 `metadata_status=unavailable`，不伪造标题或失效标记。

- 每夹 IDs 一次；需要补明细时 infos 一次（最多 1000 条），不人为拆成 20/100 条请求。
- 对已有明细复用本地索引；待补明细不算缓存命中，再次扫描仅补查它们。
- 缺明细记录不送入内容分析或收藏夹画像的模型样本，不依据明细缺失自动删除内容。
- 重复/截断 ID 清单仍不得替换此前完整快照。真实请求错误的兜底行为与正常批量读取区分。
- GET 请求只在基础请求层节流一次，移除扫描主路径的重复节流。
