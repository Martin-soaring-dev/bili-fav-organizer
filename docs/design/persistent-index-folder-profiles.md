# 持久视频索引与收藏夹画像

状态：首版实现，边界和人工复核方式已明确
更新：2026-09-25

## 目标

- 收藏夹成员关系作为当前快照维护；视频元数据作为跨收藏夹复用的长期本地索引。
- 收藏夹 ID 是目录同步主键；名称变化不影响本地身份，已消失的目录归档。
- 用实际内容而非收藏夹名字生成画像，并让画像证据进入查看、预归类和合并草稿。

## 数据位置和迁移

SQLite 默认位于 `%LOCALAPPDATA%\BiliFavOrganizer\data\library.sqlite3`。可设置
`BILI_FAV_ORGANIZER_DATA_DIR` 改用另一持久目录。主库不放在项目目录内，便于项目更新、清理或切换版本时保留索引。

第一次启动时，如果新位置还没有数据库而项目 `data/library.sqlite3` 存在，程序用 SQLite 在线备份 API 将它复制到新位置，执行 `quick_check` 后再启用副本；旧文件原样保留。若没有旧 SQLite，则从项目里的旧 JSON 导入，并在新位置创建 JSON 备份。

## 收藏夹生命周期和成员快照

- 刷新目录时按收藏夹 ID upsert 名称和数量。新 ID 默认 `active`；改名更新同一行。
- 每次目录同步同时刷新 `directory_order`，本地查看的「B 站顺序」按最近一次远端列表顺序排列。
- 之前为 `active`、本次目录中不再出现的 ID 变成 `archived`，记录归档时间；扫描选择和该夹 `folder_items` 同时清理。
- 普通选择器、本地内容查看、预归类、画像和合并建议只读取 `active` 收藏夹。归档记录只为历史和导出保留。
- 完整扫描成功后，事务性删除该夹旧的 `folder_items` 并按本次结果重建；被取消收藏或已失效的资源会从夹关系中消失。
- B 站移动或删除操作明确成功后，立即从原夹删除关系、在目标夹建立关系；不等待下一次全量扫描才修正本地树。
- 这只删除关系，不删除 `videos` 元数据。多个 active 收藏夹可通过多条 `folder_items` 关系共享同一视频记录。

## 增量视频索引和 B 站读取路径

小于等于 1000 条的收藏夹优先读取 B 站资源 ID 清单；对照本地索引，只为索引未命中的 `(type,id)` 请求元数据。查到的记录按资源键 upsert 到持久 `videos` 表。收藏夹超过 1000 条时，项目已知的 ID 接口可能只返回前 1000 条，所以必须逐页读取明细；不把 ID 接口当作大夹的完整文件树来源。分页仍受 B 站每页上限影响。

`folder_items` 是当前收藏夹成员索引，`videos` 是可复用元数据索引；两者生命周期不同。档案夹归档或完整快照发现成员删除时只删除关系；用户明确清空本地资料时才清空视频索引。

## 收藏夹简介与 B 站同步

当前目录刷新调用 `GET /x/v3/fav/folder/created/list-all`，项目只保存返回项中的收藏夹 ID、名称、数量和封面，不在刷新目录或扫描时读取收藏夹 `intro`。扫描时读取的是视频条目的 `intro` 并保存为本地视频简介，不是收藏夹简介。画像卡片上的简介上传入口会按需调用 `GET /x/v3/fav/folder/info` 读取远端简介供用户比对。

画像的 `summary` 是本地生成的收藏夹画像简介，保存在 SQLite 的 `folder_profiles`，不会自动上传。用户可在画像卡片点击「上传简介到 B 站」，预览远端简介与准备写入的文字，修改后显式确认；写入使用 `POST /x/v3/fav/folder/edit` 的 `intro` 字段，并保留当前标题、公开状态和封面。若远端标题已与本地目录名称不一致，写入会被拦截，要求先刷新目录。上传仅写回 B 站，不修改本地画像。

项目数据清理弹窗提供独立的「收藏夹画像数据」范围，默认不勾选；只选该项会删除 `folder_profiles`，不清理扫描关系或视频索引。清理前仍自动备份数据库。

## 连接与模型管理界面

Cookie 只通过两种显式方式配置：默认二维码登录，或切换到手动输入并保存；两种方式都可单独测试登录态。浏览器选择器不再作为 Cookie 回退来源。顶部「刷新计数」只重新读取本地数据库统计，不刷新 B 站目录或模型列表。

模型管理打开时默认定位到激活模型所属供应商，在模型列表滚动到激活模型并进入编辑状态。点击模型行只打开编辑，不改变激活项；「保存」和「取消」用于编辑，「激活」才切换运行模型。供应商预设由下拉菜单选择，默认「其他」用于自定义名称和地址。

## 收藏夹画像生成和新鲜度

「收藏夹画像」栏只允许对 active 收藏夹操作。生成画像前要求收藏夹有完整扫描快照，目录计数、本地关系数和完成快照一致。画像会使用该夹全部本地索引内容；若全量输入超过上下文预算，就先拆成多段分别压缩，把中间摘要暂存于本次任务内，再合并为最终画像。每条样本提供标题、视频简介、UP 主和可用标签，生成简介、主题、典型内容、范围外提示、一致性和把握度。单次输出预算同时受模型上下文、TPM、界面配置和供应商模型硬上限约束；这些限制取最小值。

画像生成提示在分页压缩、摘要合并和最终画像阶段都会注明：**默认收藏夹只能移出、不能移入**。默认夹画像应描述其现有内容适合的主题和明显不适合的内容范围；生成的默认夹简介也会包含这条操作规则，不能把默认收藏夹建议为其他内容的归类目标。

画像只有同时匹配收藏夹 ID、名称、本地成员数和完整快照时间才算最新，每次生成还会得到新的画像版本号。重扫、改名、成员数量变化或重建画像都会使基于旧版本的内容核对和合并依据过期；过期画像仍能查看，但不会进入自动分析依据。画像不直接移动任何内容。

## 内容整理的画像完整性门槛

内容归类和收藏夹合并要求每个**有内容的 active 收藏夹**都已完成扫描，并有匹配当前名称、成员数和快照时间的完整画像。画像数据须包含非空简介、至少两个主题、典型内容与范围外列表、有效一致性和 0~1 置信度。缺画像、画像字段不全、扫描未完成、目录数与本地关系数不符或画像过期时，前端显示未就绪收藏夹，服务端也拒绝启动分析、生成/提交合并任务或执行合并。执行阶段会先刷新 B 站目录，并在任何移动、删除、改名请求前再次核验画像；若目录变化使画像失效，任务停止且不发送整理写请求。

空收藏夹没有内容可供画像，会显示为不参与整理的目标；它们不会作为内容归类或 AI 合并建议的候选。手工合并草稿可以编辑，但提交和执行仍受画像门槛限制。归类目标只能选择有当前完整画像的收藏夹；新建分类也必须在完整画像集合的基础上分析。

### 内容批次的上下文预检

内容整理的批大小是逻辑批次上限，可设为 1、2、5、8、10、20、50、100、200、500 或 1000。每次 HTTP 请求发送前，程序估算 system 提示词和该批视频 JSON 的输入 token，并按 `上下文窗口 - 安全余量 - 输出预算` 检查是否可容纳。安全余量至少 512 tokens，或上下文的 15%（取较大者）；配置的最大输出仅作为上限，预算不足时多条批次先二分，单条请求则下调输出上限以留在上下文窗口内。如果连 256 个输出 token 都无法保留，程序不发请求并记录明确失败。TPM 和上下文预算不会覆盖服务商的单次输出硬上限；例如 MiMo Chat Completions 的 `max_completion_tokens` 范围最高为 131072（MiMo v2.5 为 32768），见[官方接口文档](https://mimo.mi.com/docs/en-US/api/chat/openai-api)。

估算不依赖模型专用 tokenizer，因此它是保守预检，不构成对供应商分词结果的数学保证。响应若带 `finish_reason=length`，会当作截断，不采纳结果；程序继续拆分缺失条目，单条仍截断时记为失败。批次按预检拆分的事件会显示在任务日志中。

## 画像如何进入三个界面

### 查看本地内容

收藏夹信息展示画像简介、主题、典型收纳范围、范围外提示和画像状态。每条内容显示「画像待核对」「画像核对通过」或「画像不符」；偏离判断来自最近一次预归类分析，且仅在该分析检查的画像仍是当前版本时显示。收藏夹画像过期时，项目内容行不把旧判定当成当前结论。

### 预归类方案

LLM 只会收到当前有效画像对应的有内容收藏夹，并收到画像的完整分类字段：简介、主题、典型内容、范围外提示、一致性和把握度；开始前要求所有有内容的 active 收藏夹画像完整。画像是实际分类依据，夹名只是弱提示。对已有收藏关系的条目，LLM 还会检查它是否明显偏离当前夹画像。明显符合当前画像的条目建议留在原夹；只有明显偏离且目标清楚时才建议改归其他夹或新建分类，证据不够时保留原位。分析结果记录整组画像版本、核对过的夹 ID、偏离夹 ID 和简短理由。画像被重建、刚更新或扫描快照变化后，旧分析结果会显示需要重核，分析器会重新处理使用旧版本的内容；旧结果不能确认成新方案。执行前会比较提交方案保存的版本与当前版本。

**默认收藏夹只能移出、不能移入。** 归类提示会把默认夹画像用于判断其中现有内容是否偏离，但禁止将任何内容建议移入默认收藏夹，也禁止以默认收藏夹作为新建目标。前端不提供默认夹的目的地选择，服务端在方案提交、执行启动和实际分组写入前再次拦截；已经在默认夹中的内容可以保留原位，或在证据明确时移出到其他有画像的夹/新主题。

这是模型对证据的辅助判断，不是自动搬运规则。用户仍需在预归类方案里确认、修改或跳过建议。

### 合并组草稿

合并分析要求所有有内容的 active 收藏夹画像完整，再综合完整画像、代表内容和跨夹重复数；夹名只作弱提示。空收藏夹不作为候选。每个 AI 生成的候选组保存「画像依据」、上下文收藏夹 ID 和建议生成时的整组画像版本。即使用户编辑时清除具体 AI 依据，版本基线仍保留；画像重建、改名或成员快照变化后，草稿会提示建议版本已过期，提交和执行会被拦截，直到重新生成画像和建议。手工新建的组没有 AI 建议版本基线，但提交和执行仍须通过当前画像完整性校验。

## 导入导出和回滚

兼容 JSON 导出包版本为 3，包含 active/archived 收藏夹、视频索引、画像和扫描状态。项目内旧 SQLite 在迁移后保留为人工回滚副本。导入数据前，服务先备份当前数据库；误操作时可从导出包恢复。
