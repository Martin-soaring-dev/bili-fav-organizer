## 版本治理

- **最后正式版**：`v0.210.0`，发布目标 `d62b2cf487edebc317202c7312440938ef036dd2`；三个 Windows 发行物及各自 SHA-256 校验文件，共六件。
- **主干**：`main`；发布后的修复应通过短分支、PR、CI 和实机验证进入下一版本，不得修改历史 tag 或覆盖发布附件。
- **门禁**：单元/接口回归 → Windows 构建 → 安装/升级/卸载与用户目录迁移 → 数据恢复/锁定测试 → 人工确认发布；保留可复核的运行 ID、构建 SHA、产物 hash。
- **异常**：发布工作流存在失败记录，应单独区分“已经发布的资产”和“后续重新执行发布被拒绝”；优先审查是否为防覆盖门禁正常拒绝，不强行再次发布相同版本。

## GitHub Pages 治理

目前确认存在 `docs/index.html` 与成功的 Pages build and deployment 工作流；尚未从可访问的仓库接口核实 Pages 设置中的 source/custom domain、实际对外 URL、站点内容和可见性。严禁把 Pages build success 解释为内容已审计。
- 先记录 Pages Source、构建工作流、公开 URL/访问权限和部署 artifact；
- 核查 HTML 资源引用、敏感路径、隐私内容与 broken links；
- 与 README 关系厘清后再决定是否保留、迁移或关闭 Pages；
- 未经维护者授权不变更站点可见性及历史部署。
