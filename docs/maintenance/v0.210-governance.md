## 扫描漏项诊断使用流程（#25）

1. 运行含 PR #27 的开发测试版（不是 v0.210.0 发行版）；确认 B 站登录态有效。
2. 触发数量不一致的收藏夹弹窗后点击「只读诊断漏读原因」。
3. UI 返回 `directory_count`、`paged_count`、`paged_unique_count`、`ids_count`、`ids_unique_count`、各页返回数量及差集数量。
4. **不要点自动清理**。若 `ids_count=316` 且 `paged_count=315`，应继续复查 `resource/list` 的最后一页以及 `has_more`，再利用隔离夹具修复；若两接口都只有315，则说明可能有平台可见性/计数语义差异，不能先把错误归咎于本地。
5. 诊断仅回传随机盐指纹，无法跨运行匹配；为保护隐私不会持久化用户完整收藏信息。若需原始 ID 精确对账，应在本机经过单独授权后完成，不上传敏感信息。
6. 对 164/163 进行同样的只读验证，检查是否与 316/315 共因。

诊断中断或遭遇风控时不重试写操作，保留当前未完成状态；该诊断结果不能自行解除业务整理阻断。
